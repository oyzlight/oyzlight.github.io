模板基础

核心思想：用编译时间换运行效率——编译期生成所有版本的代码

模板变量

template <> 是什么意思？

模板就像一个"代码生成器"。需要分两步理解：

第一步：主模板 <int N> —— 声明一种模式

这一行不生成任何代码，只是告诉编译器"存在这样一个递归模式"。
当代码里写 fib<10> 时，编译器代入 N=10，生成 fib<10> = fib<9> + fib<8>。
同理 N=9 → fib<9> = fib<8> + fib<7>，N=8 → ……

如果没有特化，这个递归会无限套娃（N=0 时 fib<0> = fib<-1> + fib<-2>）直到编译器报错。

第二步：全特化 <> —— 指定"当 N 恰好是 X 时，别套公式，用这个值"

全特化是递归的终止边界，和递归函数里的 if (n == 0) return 0; 作用一模一样。

速记：

  • template <int N> → “以下是泛型配方，N 后面再填”
  • template <> → “以下是精确配方，类型/值已经完全确定了”
  • 每个需要"终止递归"的值都要单独写一个 template <>

三种模板声明对比

写法 叫什么 什么时候用
template <int N> 主模板 定义通用规则，参数未被固定
template <> 全特化 为某个具体值/类型特殊处理（如递归出口）
template <typename T> 然后 struct X<T*> 偏特化 只固定部分参数（如"所有指针类型"），仅类模板支持

编译期递归计算斐波那契，运行时只是读取常量。整个递归树在编译期全部展开完毕，最终可执行文件里只有几个常量值

  • 特化版本仅在 char* 时生效
  • 编译器为每种使用的类型生成一份独立代码

智能指针

unique_ptr — 独占所有权

make_unique 比 new 更安全——避免裸指针泄漏，一次分配控制块和数据

shared_ptr — 共享所有权

weak_ptr — 弱引用，打破循环

嵌入式 C++ 实战

在 STM32 / 裸机环境里，以下 C++ 特性零开销，却大幅提升代码安全性。没有 RTTI、没有异常、没有堆分配，纯编译期魔法。

volatile —— 内存映射寄存器

volatile 告诉编译器：这个变量的值可能在你不知道的时候被硬件改变，每次读写都必须真实访问内存，禁止缓存到寄存器中，禁止优化掉"看似多余"的读写

volatile 的正确与错误用法

enum class —— 替代魔数

enum class 三大优势：① 值不污染全局作用域 ② 不同类型间不能隐式比较 ③ 可指定底层类型节省内存（uint8_t 只占 1 字节）

constexpr —— 编译期算完，运行时零开销

用模板写零开销 GPIO 封装

编译器内联后，LED::set() 只有一条 STR 指令，和手写汇编效率一样

inline 替代宏

static_assert —— 编译期断言

ISR 安全的数据传递

有限状态机 —— enum class + switch

嵌入式 C++ 不建议使用的特性

特性 原因
RTTI (typeid, dynamic_cast) 增加 vtable 大小和 ROM 占用
异常 (try/catch/throw) 栈展开需要元数据，动辄 +20KB ROM
STL 中用堆的容器 (vector, map, string) 碎片化、不确定延迟、无 malloc
iostream (cout, cin) 代码体积巨大（>50KB），不适合裸机
new / delete 同堆问题，用静态分配或内存池

嵌入式 C++ 原则：能用编译期搞定的就别拖到运行时。constexpr、template、enum class、static_assert、inline 都是零开销抽象

常见陷阱与最佳实践

  1. 悬空引用：不要返回局部变量的引用或指针
  2. 切片问题：按值传递派生类对象给基类参数时会丢失派生部分
  3. 虚析构：带虚函数的基类必须有虚析构
  4. const 正确性：不修改对象的成员函数加 const
  5. 初始化列表顺序：初始化顺序由成员声明顺序决定，不是列表顺序
  6. 三/五法则：定义了析构/拷贝/移动之一，通常需要定义全部
  7. lambda 捕获悬挂：引用捕获的变量生命周期必须长于 lambda
  8. 迭代器失效：vector 插入/删除可能导致迭代器失效
  9. 整数溢出：无符号整数下溢、有符号溢出是 UB
  10. 多线程数据竞争：共享数据必须加锁或用 atomic
