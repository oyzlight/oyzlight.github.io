CAN 通信

概述

CAN（Controller Area Network）是一种多主机的串行通信协议，广泛应用于汽车电子、工业自动化和机器人领域。相比 I2C、SPI、UART 等通信方式，CAN 具有实时性强、抗干扰能力强、传输距离远等优势。

CAN 物理层

CAN 使用差分信号传输，两条信号线分别为 CAN_H 和 CAN_L：

  • 显性电平（Dominant）：CAN_H 约 3.5V，CAN_L 约 1.5V，压差约 2V，表示逻辑 0
  • 隐性电平（Recessive）：CAN_H 和 CAN_L 均为约 2.5V，压差接近 0V，表示逻辑 1

显性电平优先级更高——当多个节点同时发送时，发送显性的节点胜出，这就是 CAN 总线仲裁的基础。

数据帧格式

标准数据帧包含以下字段：

字段 长度 说明
SOF 1 bit 帧起始，显性电平
ID 11 bit (标准) / 29 bit (扩展) 标识符，决定优先级
RTR 1 bit 远程请求
IDE 1 bit 标准帧/扩展帧标志
DLC 4 bit 数据长度 (0-8)
Data 0-8 bytes 数据域
CRC 15 bit 循环冗余校验
ACK 2 bit 应答
EOF 7 bit 帧结束

仲裁机制

CAN 总线的仲裁是通过 ID 优先级 实现的：

  1. 多个节点可同时发送数据
  2. 逐位比较 ID，发送隐性（1）的节点检测到总线为显性（0）时自动退出
  3. ID 越小，优先级越高

实际使用中的注意事项

  1. 终端电阻：总线两端必须各接 120Ω 终端电阻，否则信号会反射导致通信异常
  2. ID 规划：根据优先级给不同设备分配 ID，高优先级消息用较小 ID
  3. TJA1050 方向：收发器芯片方向不要焊反，引脚 1 对引脚 1
  4. 共模电感：在 CAN_H/CAN_L 上串联共模电感可以进一步抑制共模干扰
  5. 错误处理：CAN 控制器在错误计数超过 255 时会进入 Bus-Off 状态，需要软件恢复
